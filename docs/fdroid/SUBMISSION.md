# New app: Wave Remote (me.vwave.remote)

Prepared submission text. Nothing has been posted. Publish the release source and
v0.6 APK before opening the inclusion request so all linked inputs are available.

Wave Remote is an MIT-licensed Android remote for LG webOS TVs. It connects directly
over the local network, with pairing, buttons, a touchpad, volume control, keyboard,
inputs/apps, multiple saved TVs, and Wake-on-LAN/Bluetooth wake. It has no account,
advertising, tracking, cloud service, Play Services or downloadable executable code.

## Build and signature verification

Expo 57 / React Native 0.86.3 app; `android/` is generated by Expo prebuild.
The recipe installs official Node.js 24.22.0 with a pinned SHA-256 and uses
`npm ci --ignore-scripts` with `package-lock.json`. Packaging does not use Bun.
Expo native modules are requested from source and their bundled local-Maven AARs
are removed. React Native/Hermes and other Maven artifacts use trusted repositories.

The production certificate is pinned in `AllowedAPKSigningKeys` and matches v0.5:
`a2a5c53e76ebefe4c0c5b288904a813dc3d2a61e3802ac8066466167913ed69c`.
We request developer-signed publication with `Binaries`. Independent local
upstream and Debian/F-Droid builds passed signature copying and exact byte
comparison. F-Droid's own Python 3.13 publish command also passed into a temporary
local repository. The Debian build used `--on-server` and executed sudo provisioning;
it was a chroot test with a host-supplied SDK, not an official hosted-VM result.

The native prefix-map configuration normalizes checkout and Gradle-cache paths.
Signing preserves ZIP alignment and omits unnecessary v1/JAR entries to avoid
Python 3.13 flag rewriting during copying. The minimum Android API is 24; v2/v3
signatures verify. All 16 native libraries match between builds.

## Scanner and dependency disclosures

`scanignore` retains the Linux Hermes compiler, as permitted by F-Droid's
[toolchain policy](https://f-droid.org/en/docs/Inclusion_Policy/), and the scanner's
local-Maven declarations in three Gradle files. Other flagged files in node_modules
are removed by `scandelete`; this does not delete the whole dependency tree.
There are no blanket scanner exceptions for the app sources or APK.

Source and binary scans passed. The binary scan found no known non-free classes or
extra signing blocks; this is a scanner result, not a complete manual review.
Declared npm and Maven licenses were inventoried in the local evidence bundle.
The one APK font matches MaterialCommunityIcons.ttf byte for byte, distributed
under [Apache-2.0](https://github.com/Templarian/MaterialDesign/blob/master/LICENSE).
The website and its font are outside the Android build.

## Protocol data and network behavior

`src/me/vwave/remote/Tv.java` contains LG-signed registration data observed during
interoperability research on ThinQ: identifiers, permission names, localized app
names and a machine-generated signature. The TV checks it at pairing and can show
"LG Mobile" in its prompt. This is not the APK signing key. No ThinQ APK or
decompiled application is distributed. [NOTICE.md](../../NOTICE.md) records its
origin and the interoperability rationale; the project's MIT license does not
purport to cover LG's values or trademarks. Please review this disclosed data and
any applicable Anti-Feature labeling as part of normal inclusion review.

Cleartext LAN access is needed for SSDP device descriptions and older TVs that only
support ws://. Modern TVs use TLS with a certificate pinned on first pairing; a TV
already paired over TLS cannot be downgraded to cleartext. Pairing keys stay local.
The app depends on an LG TV's firmware, not an installed proprietary Android app
or a vendor cloud endpoint.

The release passed app/protocol tests. On a Pixel 7, the production APK installed over 0.5, kept the saved TV and showed the corrected disconnected screen. TV-facing behavior is unchanged from 0.5 and was not retested against a TV. Screenshots
represent the existing connected UI; no new captures are claimed.
